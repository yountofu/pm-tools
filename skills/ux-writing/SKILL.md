# UX 라이팅

화면 문구는 사용자가 지금 무엇을 할 수 있는지 바로 알게 쓴다. 어투는 해요체로 통일하고, 기능 설명은 "~할 수 있어요"로 쓴다.

## 기본 어투

- 해요체를 쓴다. "-습니다", "-합니다" 대신 "-어요", "-요"로 끝낸다.
- 한 문장에는 메시지 하나만 담는다.
- 쉬운 일상어를 쓴다. 개발 용어, 내부 상태 이름, 필드 이름은 화면 문구에 쓰지 않는다.

## 기능 설명은 "~할 수 있어요"

사용자가 할 수 있는 일을 알려 주는 문장은 "~할 수 있어요"로 쓴다. "~해요", "~봐요" 같은 동작 서술로 쓰지 않는다.

- 대상: 페이지 머리 설명, 화면 안내 투어의 본문과 목록, 툴팁, 빈 상태에서 다음 행동을 알려 주는 문장
- 그대로 두는 문장: 조건, 제약, 상태 정의는 원래 뜻대로 쓴다. 억지로 "~할 수 있어요"로 바꾸면 조건이 흐려진다.

| 구분 | 고치기 전 | 고친 뒤 |
| --- | --- | --- |
| 기능 설명 | 예약된 상담과 내 가용시간을 한 화면에서 봐요. | 예약된 상담과 내 가용시간을 한 화면에서 볼 수 있어요. |
| 기능 설명 | 요일 머리를 누르면 그 날짜의 가용시간 창이 열려요. | 요일 머리를 눌러 그 날짜의 가용시간만 바꿀 수 있어요. |
| 기능 설명 | 질문 은행에서 고르거나 직접 입력해 문항을 담아요. | 질문 은행에서 고르거나 직접 입력해 문항을 담을 수 있어요. |
| 조건(그대로) | '반복 시간 저장'을 눌러야 반영돼요. | 같음 |
| 제약(그대로) | 지난 날짜는 바꿀 수 없어요. | 같음 |
| 상태 정의(그대로) | 요일별 반복 시간으로 연 시간이에요. | 같음 |

## 길이

- 페이지 머리 설명은 페이지마다 한 줄로 쓴다. 상세 설명, 범위 설명, 다른 화면으로 가라는 안내를 여러 줄로 붙이지 않는다.
- 화면 구조의 빈틈을 설명 문장으로 메우지 않는다. 필요하면 화면 구조를 고친다.
- 화면 안내 투어 말풍선은 예외로, 제목 한 줄, 본문 1~2문장, 필요하면 짧은 목록을 쓴다.
- 오류, 빈 상태, 되돌릴 수 없는 동작의 확인 창은 남기되 한 문장으로 줄인다.

## 상황별 예시

| 고치기 전 | 고친 뒤 |
| --- | --- |
| 파일이 업로드되었습니다. | 파일이 업로드됐어요. |
| 저장에 실패하였습니다. 다시 시도해 주십시오. | 저장에 실패했어요. 다시 시도해 주세요. |
| 입력값이 올바르지 않습니다. | 입력값을 확인해 주세요. |
| 해당 기능은 관리자만 이용 가능합니다. | 관리자만 이용할 수 있어요. |
| 담당 학생의 리포트를 모아 보여요. | 담당 학생의 리포트를 확인할 수 있어요. |

## 쓰기 전 확인

- 문구에 적는 동작(저장 조건, 반영 시점, 버튼 이름)은 실제 화면 동작과 맞춘다. 확인하지 못한 내용은 쓰지 않는다.
- 버튼 이름을 문구에 쓸 때는 화면에 보이는 이름을 그대로 쓴다.
- 문구를 i18n 파일에 둔다면 같은 변경에서 키를 추가한다.
